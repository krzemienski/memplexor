# Memplexor

> Project-local memory for Claude Code. Auto-orient at session start, save
> progress before compaction or stop, generate per-project guidelines.

`memplexor` is a Claude Code plugin that gives every project a durable, file-based
memory layer at `.claude/memory/`. New sessions pick up where the last one left off.
Progress is saved automatically before compaction and on stop. Per-project
conventions are generated once and updated on demand.

## What you get

- **`/setup`** — analyze the repo and bootstrap `.claude/memory/` + a generated
  `project-guidelines` skill. Idempotent.
- **SessionStart hook** — injects `CURRENT.md` + last 3 history entries into every
  new session.
- **Stop + PreCompact hooks** — append to `HISTORY.md`, atomically rewrite
  `CURRENT.md`, write a per-session note. Dup-suppressed within 60 s.
- **`/memory-status`** — read-only health check.
- **`/memory-refresh`** — re-analyze the project after stack changes.
- **`/memory-save`** — manual checkpoint with optional `--title` and `--session-note`.
- **`/memory-prune`** — archive (never delete) old session notes + history entries.
- **`project-guidelines` skill** — meta-skill explaining how the generated
  per-project skill works.

## Install

### Local install (development)

```bash
# Clone the repo
git clone https://github.com/krzemienski/memplexor.git
cd memplexor

# Validate the plugin manifest (uses the real claude CLI)
claude plugin validate .

# Option A — symlink into Claude Code's user plugin dir (recommended for hacking)
mkdir -p ~/.claude/plugins
ln -sfn "$PWD" ~/.claude/plugins/memplexor

# Option B — load it ad-hoc for a single session (no install)
cd /path/to/any-project
claude --plugin-dir /path/to/memplexor
```

Verify it loaded:

```bash
claude --plugin-dir /path/to/memplexor plugin list  | grep memplexor
claude --plugin-dir /path/to/memplexor plugin details memplexor
```

You should see:

```
memplexor 0.1.0
  Project-local memory layer for Claude Code: …
Component inventory
  Skills (6)  memory-prune, memory-refresh, memory-save, memory-status, project-guidelines, setup
  Hooks (3)   SessionStart, Stop, PreCompact  (harness-only — no model context cost)
Projected token cost
  Always-on:   ~261 tok   added to every session
```

### Marketplace install

When published:

```
/plugin install memplexor
```

## First-time setup

In any project:

```
/setup
```

This will:

1. Inspect package manifests + config files in `$PWD`
2. Detect stack, build/test/lint commands, key directories
3. Create `.claude/memory/{context,progress,sessions}/`
4. Seed `.claude/memory/context/CURRENT.md`
5. Append a `setup complete` entry to `.claude/memory/progress/HISTORY.md`
6. Generate `.claude/skills/project-guidelines/SKILL.md`
7. Report what changed

Safe to re-run. Preserves user-authored memory by default.

## How sessions stay oriented

```
New session
   ↓
SessionStart hook fires
   ↓
hooks/session-start.sh reads .claude/memory/
   ↓
Emits JSON: hookSpecificOutput.additionalContext
   ↓
Claude opens the session already knowing:
   - What this project is
   - What was done in the last 3 sessions
   - What's next
```

## How progress is preserved

```
Session ends (Stop) — or — context about to compact (PreCompact)
   ↓
hooks/session-save.sh fires
   ↓
Appends a timestamped entry to HISTORY.md
   ↓
Atomically rewrites CURRENT.md
   ↓ (preserves your Open Questions + Warnings sections)
Writes .claude/memory/sessions/<ISO-date>.md
```

If the same event fires twice within 60 s with the same title, the second is
suppressed.

## Memory layout

```
your-project/
└── .claude/
    ├── memory/
    │   ├── context/
    │   │   └── CURRENT.md        # latest snapshot, rewritten atomically
    │   ├── progress/
    │   │   └── HISTORY.md        # append-only log of every event
    │   ├── sessions/
    │   │   └── 2026-05-27T16-43-37.md   # per-session notes
    │   └── archive/              # populated by /memory-prune
    └── skills/
        └── project-guidelines/
            └── SKILL.md          # per-project rules, generated by /setup
```

## Command reference

| Command | Purpose | Key flags |
|---|---|---|
| `/setup` | Bootstrap memory + skill | `--dry-run`, `--refresh`, `--force`, `--preserve-memory`, `--help` |
| `/memory-status` | Health check (read-only) | `--verbose`, `--json`, `--help` |
| `/memory-refresh` | Re-analyze + refresh generated files | `--skill`, `--context`, `--hooks`, `--all`, `--dry-run`, `--force`, `--help` |
| `/memory-save` | Manual checkpoint | freeform text, `--title "..."`, `--session-note`, `--help` |
| `/memory-prune` | Archive old sessions/history | `--keep-sessions N`, `--keep-history N`, `--archive`, `--summarize`, `--dry-run`, `--help` |

## Hook reference

Registered in `hooks/hooks.json`:

| Event | Script | What it does |
|---|---|---|
| `SessionStart` | `hooks/session-start.sh` | Reads memory, injects `additionalContext` |
| `Stop` | `hooks/session-save.sh` | Saves to HISTORY/CURRENT/sessions |
| `PreCompact` | `hooks/session-save.sh` | Same script, title = `pre-compact save` |

Hooks **fail open** — any internal error exits 0 so Claude Code is never blocked.

## File format examples

### CURRENT.md (generated)

```markdown
<!-- Generated by Memplexor -->
# Current Project Context

**Last updated:** 2026-05-27T16:00:00-04:00

## Where We Are
* Building auth refactor.

## Next Steps
* Add integration tests for token refresh.

## Open Questions
* Should sessions use JWT or opaque tokens?    # ← preserved across saves

## Warnings or Constraints
* Cannot break /v1/auth API consumers.         # ← preserved across saves
```

### HISTORY.md entry (append-only)

```markdown
## 2026-05-27T16:43:37-04:00 — session stop

* Hook event: Stop
* Transcript: `/var/folders/.../transcript.jsonl`
* Files touched (recent):
    * src/auth/service.ts
    * src/auth/tokens.ts
```

### Session note

```markdown
# Session Notes

**Timestamp:** 2026-05-27T16:43:37-04:00
**Hook Event:** Stop
**Title:** session stop
**Transcript Source:** /var/folders/.../transcript.jsonl

## Summary
Automatic checkpoint written by Memplexor on Stop.

## Files Touched
* src/auth/service.ts
* src/auth/tokens.ts
```

## Customizing templates

Templates live in `templates/`:

- `templates/CURRENT.md`
- `templates/HISTORY.md`
- `templates/project-guidelines.SKILL.md`

Edit them and re-run `/setup --refresh` to regenerate.

## Retention tuning

Defaults:

- `/memory-prune` keeps the newest 20 session notes and 100 HISTORY entries.
- Older items are **moved** to `.claude/memory/archive/`, never deleted.

Override:

```
/memory-prune --keep-sessions 50 --keep-history 200 --summarize
```

## Adding hooks

To add a new hook event, edit `hooks/hooks.json` and add the event +
command entry following the existing pattern. All hook scripts should:

- Read payload JSON from stdin
- Resolve project root: payload `cwd` → `$CLAUDE_PROJECT_DIR` → `pwd`
- Use atomic writes (tmp + rename)
- Exit 0 on any internal error

## Troubleshooting

**SessionStart didn't inject context.**
Check that `.claude/memory/context/CURRENT.md` exists in the project root. Run
`/memory-status`. If memory is missing, run `/setup`.

**Hooks aren't firing.**
Check `/plugin list` to confirm `memplexor` is loaded. Verify
`${CLAUDE_PLUGIN_ROOT}/hooks/session-start.sh` is executable. Hooks fail open,
so check Claude Code logs for stderr from the scripts.

**`python3` not available.**
The hook scripts require `python3` for JSON encode/decode. Install Python 3 or
edit the scripts to use a different JSON tool.

**HISTORY.md is huge.**
Run `/memory-prune --summarize`.

**I edited CURRENT.md and the save hook overwrote it.**
The save hook preserves your `## Open Questions` and `## Warnings or Constraints`
sections verbatim. Other sections are regenerated. Put manual content in those
sections.

## Security & privacy

- Memplexor **never writes secrets**. `/memory-save` refuses lines matching
  common secret patterns (`API_KEY=`, `sk-...`, `ghp_...`, `AKIA...`, etc.).
- Hooks extract only **file paths** from tool_use blocks in the transcript,
  capped at 15 entries. No raw transcript dump.
- All memory lives in `$PWD/.claude/memory/`. Nothing leaves the machine.

## Version control

Two reasonable approaches:

**Commit the memory** (for teams sharing context):

```
# Just include it
git add .claude/memory/
```

**Ignore the memory** (for personal notes):

```gitignore
.claude/memory/
```

Either works. Memplexor doesn't care. The skill file at
`.claude/skills/project-guidelines/SKILL.md` is usually worth committing either
way.

## Extension points

- **Templates:** edit `templates/*.md`
- **Hook scripts:** edit `hooks/session-{start,save}.sh`
- **Hook registration:** edit `hooks/hooks.json`
- **Commands:** add a new `commands/<name>.md` with YAML frontmatter
- **Skill:** edit `skills/project-guidelines/SKILL.md` for the meta-skill
  documentation; edit `templates/project-guidelines.SKILL.md` for the
  generated per-project skill

## Testing & validation

A complete functional-validation harness lives at `tests/validate.py`. It
runs against the **real** Claude Code CLI (no mocks):

```bash
pip install claude-code-sdk        # one-time
python3 tests/validate.py --quick  # manifest + hook scripts only (no LLM calls, ~2 s)
python3 tests/validate.py          # + live SDK subprocesses (~70 s)
python3 tests/validate.py --bench  # + latency benchmarks
```

The harness:

- Validates `plugin.json`, `hooks.json`, every command frontmatter
- Runs `claude plugin validate` against the manifest
- Spawns each hook script with controlled JSON payloads on stdin
- Checks atomic-write integrity (`.tmp.*` cleanup)
- Verifies content-bearing CURRENT.md sections survive save-hook rewrites
- Verifies dup-suppression within 60 s and distinct titles within 60 s
- Spawns real headless Claude sessions via `claude --plugin-dir`
- Confirms SessionStart hook injects orientation header + seeded markers
- Confirms Stop hook appends HISTORY + writes session note after subprocess exit
- Times session-start, session-save, and measures injected-context token size

### Benchmark results (Opus 4.7, MacBook Pro M-series, 2026-05-27)

| Metric | p50 | p95 | Target |
|---|---|---|---|
| SessionStart hook latency | 68 ms | 73 ms | < 200 ms |
| Stop/PreCompact hook latency | 100 ms | 144 ms | < 500 ms |
| Injected-context size | — | ~298 tokens (1.2 KB) | < 3000 tokens |

The plugin adds ~261 always-on tokens per Claude Code session and ~298
tokens of dynamic project context. Hooks complete in under 150 ms p95 on
warm storage.
